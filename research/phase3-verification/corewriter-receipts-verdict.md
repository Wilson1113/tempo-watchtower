## Verdict: **SOUND WITH CAVEATS**

The core problem re-verifies as real, current, and unaddressed by Hyperliquid Labs as of today. Independent, exhaustive search (GitHub API, crates.io, npm, DuckDuckGo web search) found **zero** tools that do the forward-direction (HyperEVM→HyperCore) CoreWriter outcome correlation this pitch proposes — confirming the deck's own competitive scan rather than contradicting it. Nothing here is fatal.

**Chainstack docs quotes** — VERIFIED via fresh WebFetch of `docs.chainstack.com/docs/hyperliquid-corewriter`: both quotes in the deck are accurate verbatim ("sendRawAction emits its log and the EVM transaction succeeds whether or not HyperCore accepts the action"; "CoreWriter does not return a value to the caller... This is good news for the pitch's durability argument (Hyperliquid has no incentive to "fix" documented-as-intended behavior) but the deck should cite it directly — it's a stronger, first-party-adjacent confirmation of "fire-and-forget by design" than what's currently in §2.

**Hyperliquid's own CoreWriter docs page** — VERIFIED via fresh WebFetch: confirms gas cost (~25,000 / ~47,000 in practice) and the "delayed a few seconds, appears twice in explorer" behavior, and **contains no error-handling or failure-detection documentation whatsoever**. **Architecture claim (fire-and-forget by design vs. a fixable bug):** the evidence supports "by design," not "bug." Chainstack's own docs treat it as expected, common developer-confusion behavior with known root causes (account setup, funding, size), not a defect the team is triaging. This is consistent with the deck's Impact-section framing ("architectural... doesn't close on its own") — I found nothing to contradict it, and the Chainstack framing above actually strengthens it.

## TAM / business-model sanity check

The deck's population estimate ("dozens, not thousands" of active CoreWriter integrators) is plausible and, if anything, slightly generous rather than inflated. My fresh GitHub counts landed on the same raw numbers (9 for "corewriter," 17 for "hyperevm hypercore"), but a meaningful fraction of the 17 — the arbitrage scanner, the yield-signal tool, the stablecoin dashboard, the balance CLI, the API wrappers — don't actually call CoreWriter at all; they touch HyperEVM or HyperCore in some unrelated way. The true count of teams that would need this specific tool (contracts/bots that call `0x3333...3333` and need to know what happened) is closer to the low end of "dozens," possibly single-to-low-double digits of real near-term paying prospects. The deck already prices this honestly (modest recurring revenue, explicitly not a venture-scale platform story on its own, expansion path contingent on ecosystem growth) — this check confirms that caution was warranted, it doesn't add new bad news. The free-tier-OSS-to-paid-hosted-alerting shape (Chainstack/Tenderly-Alerts analogy) is a real, understood SaaS pattern and not something I found reason to doubt, though the deck itself already flags the pricing-page comparison as unverified (evidence appendix #14) — that flag should stay.
